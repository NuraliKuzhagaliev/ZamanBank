# Zaman Bank

**Интерактивный fintech-концепт для хакатона: финансовый кабинет, цели накопления и помощник с текстовым и голосовым интерфейсом.**

Zaman демонстрирует пользовательский путь от знакомства с сервисом до входа в кабинет, просмотра примерных операций и создания цели. Интерфейс поддерживает **English / Русский**; по умолчанию выбран английский, настройка сохраняется в браузере.

[Открыть сайт на GitHub Pages](https://nuralikuzhagaliev.github.io/ZamanBank/)

## Возможности

| Раздел | Реализовано |
| --- | --- |
| Главная и информационные страницы | Описание концепта, возможностей и исламских финансов, разделы «О проекте» и «Контакты» |
| Демо-вход и регистрация | Формы с клиентской валидацией, локальное состояние пользователя и выход |
| Финансовый кабинет | Вымышленный баланс 250 000 ₸, примеры поступлений/списаний и карточки целей |
| Цели накопления | Создание цели с названием, целевой суммой и сроком; сохранение в браузере |
| AI-помощник | Отдельная страница чата и плавающий виджет; ответы через серверную функцию Groq или локальные заготовки при отключённом endpoint |
| Голосовой интерфейс | Диктовка сообщения и озвучивание ответа на странице помощника через Web Speech API |
| Демо-журнал | Просмотр вымышленных записей, фильтры по пользователю, типу действия и статусу, окно подробностей |

**Это концепт, а не действующий банк.** В текущем репозитории нет Flask-бэкенда, PostgreSQL, настоящих банковских счетов или серверной авторизации. Финансовый кабинет работает в mock-режиме; серверная функция обслуживает только AI chat.

## Технологии

- **Фронтенд:** HTML, CSS, JavaScript с ES-модулями; без сборки и внешних npm-зависимостей.
- **Локальное хранение:** `localStorage` для демо-профиля, состояния входа, целей и языка.
- **AI:** `api/chat.js`, серверная функция для Vercel, Groq Chat Completions API.
- **Голос:** Web Speech API браузера.
- **Разработка и проверки:** Node.js, встроенный HTTP-сервер и `node:test`.

## Локальный запуск

Рекомендуется **Node.js 22+**. Установка npm-пакетов не требуется.

```bash
git clone https://github.com/NuraliKuzhagaliev/ZamanBank.git
cd ZamanBank
npm run dev
```

Откройте **http://127.0.0.1:4173**.

В Windows PowerShell, если команда `npm` блокируется политикой выполнения, используйте:

```powershell
npm.cmd run dev
```

Можно запустить сервер напрямую:

```bash
node server.cjs
```

Другой порт:

```powershell
# Windows PowerShell
$env:PORT = "4174"
node server.cjs
```

```bash
# Linux / macOS
PORT=4174 node server.cjs
```

Открывайте сайт через HTTP-сервер: браузерные ES-модули могут не работать при запуске HTML через `file://`.

`server.cjs` обслуживает только статические файлы. Он **не выполняет** `api/chat.js`: AI-запросы идут на адрес, заданный в `ai-config.js`.

## Как попробовать демо

1. На главной нажмите **«Попробовать демо»**.
2. Введите вымышленные email и пароль от 6 символов. Можно также воспользоваться страницей регистрации.
3. В кабинете посмотрите пример баланса и операций.
4. Нажмите **«+ Создать цель»**, укажите название, сумму от 1000 ₸ и срок не раньше текущей даты.
5. Обновите страницу: цель сохранится в этом браузере для выбранного email.
6. Откройте помощника, отправьте вопрос или используйте готовую подсказку. На отдельной странице чата можно попробовать микрофон и озвучивание.
7. После демо-входа откройте `admin_panel.html`, чтобы посмотреть фильтрацию примерного журнала.

Mock-вход не проверяет пароль и не создаёт защищённую сессию. Пароль не сохраняется и не отправляется на сервер при включённом mock-режиме. Email и данные демо-профиля сохраняются локально.

Новые цели начинают с нулевой накопленной суммы. Добавление взносов, изменение баланса и редактирование/удаление целей в текущем интерфейсе не реализованы.

## AI: конфигурация и режимы

Финансовые данные и AI настраиваются независимо:

| Настройка | Текущее значение и поведение |
| --- | --- |
| `USE_MOCK` в `api.js` | `true`: вход, цели, операции и журнал работают локально |
| `CHAT_ENDPOINT` в `ai-config.js` | `https://zamanbank-ai.vercel.app/api/chat`: браузер отправляет вопросы в эту функцию |
| `GROQ_API_KEY` | Серверная переменная окружения функции; никогда не добавляйте её в браузерный JS |
| Модель в `api/chat.js` | `openai/gpt-oss-20b`; задана в коде, отдельной env-переменной модели нет |

При непустом `CHAT_ENDPOINT` чат сразу использует удалённую функцию. Если ключ отсутствует, функция возвращает `503`; при других ошибках интерфейс показывает сообщение. **Автоматического перехода на локальные заготовки нет.**

Чтобы явно включить локальные ответы без сетевого запроса, установите в `ai-config.js`:

```js
export const CHAT_ENDPOINT = '';
```

При этом оставьте `USE_MOCK = true`. Локальные ответы — простые заготовки по ключевым словам, преимущественно на русском; это не языковая модель.

Помощник объясняет возможности демо. Он не получает реальные банковские данные и не создаёт цели, платежи или переводы. Успешный ответ функции содержит `suggested_action: null`.

### Подключение функции на Vercel

Статический фронтенд может оставаться на GitHub Pages, а AI-функция — работать в Vercel.

1. Импортируйте репозиторий в Vercel с корнем проекта `./`. Фронтенду не требуется команда сборки.
2. Задайте `GROQ_API_KEY` в окружении Production и создайте новый deployment.
3. Укажите адрес своего deployment с путём `/api/chat` в `ai-config.js`.
4. Обновите `SITE_ORIGINS` в `api/chat.js`, если используете другой домен.
5. Опубликуйте изменённую конфигурацию фронтенда и проверьте отправку вопроса.

В текущем списке разрешены:

- `https://nuralikuzhagaliev.github.io`
- `https://zamanbank-ai.vercel.app`
- `http://127.0.0.1:4173`
- `http://localhost:4173`

Origin включает протокол, домен и порт, но не путь `/ZamanBank/`. Если меняете локальный порт, добавьте его origin отдельно. Доступность опубликованного endpoint и валидность ключа нужно проверять на deployment: наличие адреса в коде этого не подтверждает.

Для GitHub Pages используются файлы из корня; `.nojekyll` присутствует. GitHub Pages сам по себе серверную AI-функцию не исполняет.

## Контракт AI API

`POST /api/chat` принимает `Content-Type: application/json` и разрешённый `Origin`.

```json
{
  "message": "How do I create a savings goal?",
  "locale": "en",
  "history": [
    { "role": "user", "content": "Hello" },
    { "role": "assistant", "content": "Hello! How can I help?" }
  ]
}
```

Успешный ответ:

```json
{
  "text": "Open the Dashboard and click + Create goal.",
  "suggested_action": null
}
```

- `message`: непустая строка до 1000 символов.
- `locale`: `ru` для русского; остальные значения выбирают английский.
- `history`: необязательный массив; используются последние 8 сообщений с ролями `user` / `assistant`, до 1000 символов каждое.
- Функция ограничивает длину тела запроса; большая история может превысить общий лимит даже при допустимой длине отдельных сообщений.
- `OPTIONS` обрабатывает CORS preflight. Запросы без разрешённого Origin отклоняются.
- Ошибки: `400` — неверные данные; `403` — Origin; `413` — размер; `415` — тип содержимого; `503` — отсутствует ключ; `429` — лимит провайдера; `502` — ошибка Groq или сети.

В коде нет собственного ограничения частоты запросов. Проверка Origin не предотвращает расходование квоты автоматизированными клиентами; для публичного использования нужен отдельный механизм ограничения.

## Данные и границы реализации

- Баланс, операции и записи журнала подготовлены для демонстрации. Журнал не записывает реальные события пользователя.
- Цели сохраняются под ключом, связанным с email. Это разделение локальных демо-данных, а не контроль доступа.
- Выход очищает состояние входа, но сохраняет цели, демо-профиль регистрации и выбор языка.
- Данные не синхронизируются между устройствами и зависят от браузера и origin. GitHub Pages, Vercel и localhost используют отдельные хранилища.
- Страница `admin_panel.html` не имеет серверной проверки роли и не является защищённой панелью администратора.
- При удалённом AI текущий вопрос и ограниченная история передаются через функцию в Groq. Реальные пароли, реквизиты и личные финансовые сведения вводить не следует.
- Распознавание речи зависит от браузера, разрешения микрофона и доступности его speech-сервиса; работа офлайн не гарантируется. Код выбирает `en-US` или `ru-RU`.
- Контактная страница информационная; серверной отправки формы нет.
- `setBaseUrl()` и `setMockMode()` в API-слое оставлены как точки интеграции. Отключение mock-режима не добавляет отсутствующий банковский бэкенд.

## Проверки

```bash
npm run check
```

В PowerShell при необходимости: `npm.cmd run check`.

Команда запускает проверку локальных ссылок и синтаксиса корневых JS-файлов, затем **6 тестов AI-функции**. Тесты проверяют разрешённые origins, отклонение неверного origin и длинного сообщения, передачу истории, язык ответа и обработку лимита Groq.

Groq в тестах подменяется: настоящий ключ не нужен. Эти проверки не подтверждают доступность живого API, работу микрофона, визуальное качество или весь пользовательский сценарий.

Для ручной проверки пройдите демо-вход, создание цели и перезагрузку, переключите EN/RU, проверьте фильтры журнала, чат и голос в поддерживаемом браузере.

## Дальнейшее развитие

Для перехода от концепта к сервису потребуются серверная авторизация и проверка ролей, база данных с контролем доступа, полноценное управление целями, настоящий аудит событий, ограничения запросов, мониторинг и тесты пользовательских сценариев. Интеграция с финансовыми продуктами требует отдельной технической и юридической проработки.
